4. **`## Workflow`** — numbered steps. For Phase 3, write steps 1-4 below. (Steps 5+ for vectors and report are Phase 4/5.)

   **Step 1: Fetch candidate transcripts (Checkpoint 1)**
   - Run `bun scripts/fetch-transcript.js <user query>`
   - Display the numbered list verbatim to the user
   - Wait for the user to reply with a number (1-8) — this is Checkpoint 1

   **Step 2: Confirm transcript (Checkpoint 2)**
   - Take the selected `<transcript_id>` from the list metadata you preserved in Step 1
   - Run `bun scripts/fetch-transcript.js summary <transcript_id>`
   - Parse the JSON `{ id, title, overview, action_items }`
   - Display: title · date · participants · overview
   - Ask the user `Confirm this transcript? (y/n)` — this is Checkpoint 2
   - On `n`, return to Step 1's list. On `y`, proceed.

   **Step 3: Classify call type (CLASS-01)**
   - Read the transcript overview and action_items from Step 2
   - Classify into exactly one of: `internal`, `sales`, `general`
   - Use these signals:
     - `internal` — all participants share a company domain matching the workspace internal list (leadgrow.ai, leadgrowgtm.com); discussion of internal projects, hiring, ops, roadmap
     - `sales` — at least one participant on a non-internal domain; discussion of pricing, scope, problems, proposals, demos, discovery questions
     - `general` — neither pattern fits cleanly (customer success check-in, partner sync, advisor call, podcast guest, etc.)
   - If `sales`, sub-classify into one of: `discovery`, `demo`, `proposal`
     - `discovery` — first or early call; questions outweigh demonstrations; no pricing yet
     - `demo` — product walkthrough or capability presentation dominates
     - `proposal` — pricing, scope of work, terms, or close attempt is the primary content
   - State your classification confidence to yourself as `high` or `low`. Confidence is `low` when:
     - Multiple call types are mixed (e.g. proposal call that drifts into discovery), OR
     - Participant domains are ambiguous (only generic gmail/outlook addresses), OR
     - Overview is short (<2 sentences) and action_items don't disambiguate

   **Checkpoint 3 — Confirm classification (only when confidence is low)**
   - When confidence is `high`, skip Checkpoint 3 and proceed to Step 4
   - When confidence is `low`, show the user:
     ```
     Checkpoint 3 — Classification uncertain
     My read: <type> (<sub-type if sales>)
     Why uncertain: <one-line reason>
     Confirm or override? (internal / sales:discovery / sales:demo / sales:proposal / general)
     ```
   - Wait for the user's reply and use their answer as the final classification
